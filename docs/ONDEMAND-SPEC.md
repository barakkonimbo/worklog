> v0.7.2 הוסיף `/worklog help` — ריכוז כל הפקודות (סקיל + CLI) במסך אחד.
> מטרה: לסגור את הפער "הדליברי נעול ל-20:30" — לאפשר **"שלח עכשיו"**, **תצוגת-סטטוס מאוחדת** ו**בחירת שפת-פלט**
> מתוך `/worklog`, בלי לגעת בלוגיקת התזמון הקיימת ובלי שבירת תאימות-לאחור.

## ההקשר — הצינור הקיים והפער

| ריצה | פקודה | מה קורה |
|------|-------|---------|
| 18:00 (קבוע, א׳–ה׳) | `--daily` | סיכום + toast. **לא** מייל, **לא** יומן |
| 20:30 (אם email/cal מופעל) | `--daily --email` | סיכום + מייל (אם enabled) + סנכרון יומן (אם enabled) |
| א׳ 08:00 | `--weekly --email` | סיכום שבועי + מייל |

**3 הפערים:**
1. **אין "שלח עכשיו".** סעיף 3 ב-skill (`--daily`) יוצר סיכום **בלי דליברי**. כדי לשלוח עכשיו צריך ידנית `--daily --email` — לא מתועד ב-skill.
2. **הדגל `--email` מטעה.** הוא בעצם "ריצת הדליברי הסופית" ושולט גם על היומן (`trySyncCalendar` נשען על `want.email`). on-demand צריך פועל מפורש, לא דגל בשם של ערוץ אחד.
3. **אין תצוגת-על.** יש `show today` (קריאת קובץ) ו-`config` (הגדרות) בנפרד — אבל לא מסך אחד: *מה תועד היום + מצב היעדים + הריצה הבאה*.

## מודל הפקודות (ב-skill `/worklog`)

### `send` — דליברי on-demand
- **`worklog send`** → regenerate של סיכום היום, ואז שלח **לכל יעד מופעל** (מייל אם `email.enabled`, יומן אם `calendar.enabled`).
- **בורר יעד:** `worklog send email` / `worklog send calendar` — שליחה ליעד יחיד (עדיין רק אם אותו יעד `enabled`; הבורר אינו עוקף `enabled`).
- מאחורי הקלעים: `worklog-summary.js --daily --deliver [--only email|calendar]` (ראו refactor למטה).
- **התנהגות-קצה:**
  - אין יעד מופעל → **לא שולח**; מציג: "מייל ויומן כבויים — להפעלה: `/worklog` (config) או setup חד-פעמי."
  - אין רשומות היום → **לא שולח**; מציג: "אין פעילות מתועדת היום."
  - regenerate נכשל (Claude לא זמין) → נופל ל-fallback summary (כמו היום) ואז שולח אותו.

### `status` — תצוגת-על
**`worklog status`** (מאחורי הקלעים: `worklog-config.js status`) מציג בלוק אחד:
- **היום:** מספר רשומות + רשימת הפרויקטים (מתוך `<today>.md`); האם `summary-<today>.md` כבר נוצר.
- **יעדים:** מייל `on/off` + מוגדר? (קיום `.email-cred`) + כתובת היעד; יומן `on/off` + מוגדר? (קיום `.calendar-cred`).
- **שפה:** שפת-הפלט הנוכחית.
- **תזמון:** שורות ה-`describe()` הקיימות (18:00 קבוע · מייל/יומן סופי · שבועי).

### שפת פלט — `language`
- **`worklog language English`** (או `language he` / `language עברית` / כל שם שפה) — נשמר ב-`config.language`.
- מוזרק לראש ה-prompt של הסיכום היומי **והשבועי**: "כתוב את כל הסיכום, כולל הכותרות, ב<language>".
- ברירת מחדל **עברית** → אין שינוי התנהגות קיים. ההיקף: **תוכן הסיכום** (מה שנכתב לקובץ ונשלח למייל/יומן). מחרוזות-מעטפת קצרות (אייקוני toast וכד') לא מתורגמות בשלב זה.

### `help` — ריכוז כל הפקודות (v0.7.2)
- **`worklog help`** (מאחורי הקלעים: `worklog-config.js help`) — מדפיס במסך אחד את כל הפקודות: פעולות הסקיל `/worklog` (show/status/summary/week/send/language) **וגם** ה-CLI הישיר (config/summary/email/calendar/log). read-only; נחשף ב-SKILL.tpl כ-Quick reference בראש.

## רכיבים לבנייה (refactor מינימלי, תאימות-לאחור מלאה)

1. **`worklog-summary.js`** — הפרדת הדליברי מהשם `--email` + שפה + בורר:
   - `want.deliver = argv.includes('--deliver') || argv.includes('--email')` — `--email` נשאר **alias** (ה-scheduler ב-`worklog-schedule.js` ממשיך לרשום `--daily --email`; אין צורך לגעת בו).
   - להחליף את השימושים הפנימיים `want.email` → `want.deliver` (גם לשליחת המייל וגם ל-`trySyncCalendar`).
   - **בורר:** `--only email|calendar` — אם נתון, לבצע רק את אותו ערוץ (עדיין נשלח רק אם אותו ערוץ `enabled`).
   - **שפה:** לקרוא `config.language` (ברירת מחדל "עברית") ולהזריק שורת-הוראה לראש ה-prompt בשני הסיכומים.
   - בכותרת ההתראה: כשהיתה שליחה בפועל, לשקף "(סופי · 📧/🗓️ נשלח)" כמו היום.
   - **גארד "אין רשומות":** ב-`doDaily`, כש-`!content` — לכתוב את ה-placeholder אבל **לדלג על הדליברי** (return לפני המייל/היומן).

2. **`worklog-schedule.js`** — `defaultConfig()`: להוסיף `language: 'עברית'` (top-level); `describe()` יציג שורת שפה.

3. **`worklog-config.js`** — תת-פקודה `status` + מפתח `language`:
   - `status`: טוען config, סופר רשומות + פרויקטים מ-`<today>.md`, בודק קיום `.email-cred`/`.calendar-cred` ו-`summary-<today>.md`, ומדפיס בלוק מאוחד (כולל `schedule.describe(c)`).
   - `language <value>`: שומר `c.language` (ולכן `load()` צריך לכלול `language`).

4. **`SKILL.tpl.md`** — להוסיף סעיפי `send` · `status` · `language`; להבהיר שסעיפי summary (3/4) הם **יצירה-בלבד**, ו-`send` הוא **יצירה+שליחה**.

5. **build + deploy** — bump VERSION (0.7.0 → 0.7.1), עדכון כל המסמכים, re-pack zip, ship ל-`youleap-Implementers/Features` + push לשני הריפו.

## מקרי קצה ידועים

| מקרה | התנהגות |
|------|---------|
| `send` בלי יעד מופעל | לא שולח; מסביר איך להפעיל |
| `send` בלי רשומות היום | לא שולח; "אין פעילות מתועדת היום" |
| `send email` אך מייל כבוי | מסביר שמייל כבוי (הבורר אינו עוקף `enabled`) |
| regenerate נכשל (Claude לא זמין) | fallback summary ואז שליחה (כמו היום) |

| `language` לא מוגדר | ברירת מחדל "עברית" — התנהגות זהה לקיים |

## לא בסקופ (עתידי)
- **one-shot override** ליעד כבוי — נדחה (המשתמש בחר "רק מופעלים").
- **תרגום מחרוזות-המעטפת** (toast/headings/כותרות אירוע) — שלב ב' אם יתבקש; כרגע השפה שולטת על תוכן הסיכום בלבד.
- **דליברי שבועי on-demand** — מתקבל "בחינם" דרך `--weekly --deliver` (המייל בלבד; אין סנכרון בלוקים שבועי ליומן). לא נחשף ב-`send` בשלב זה.
- **עדכון בזמן-אמת / שעות חדשות** — כבר נשלט דרך תזמון + config.
