# החלטות תכנון (ADR) — Work Journal

תיעוד ההחלטות המשמעותיות וההנמקה שלהן, כולל מלכודות שנתקלנו בהן ופתרנו.
פורמט: החלטה → הקשר → הנמקה → השלכות.

---

## D1 — לא Skill לבדו, אלא CLAUDE.md + Hooks
**הקשר:** הדרישה "תמיד נטען בכל סשן". **הנמקה:** Skill נטען לפי דרישה בלבד; רק `CLAUDE.md`
הגלובלי ו-hooks נטענים דטרמיניסטית בכל סשן. **השלכה:** המוצר אינו skill עצמאי → דורש installer.

## D2 — אחסון: קובץ אחד ליום, מתויג בפרויקט
**הקשר:** עבודה על כמה פרויקטים ביום. **הנמקה:** סיכום סוף-יום צריך לראות את כל התמונה במקום אחד;
תיוג `[project]` שומר הפרדה בלי לפצל קבצים. **השלכה:** `projectFromCwd` נגזר אוטומטית, ניתן לכפות ב-`--project`.

## D3 — תיעוד היברידי
**הקשר:** הסתמכות על קלוד בלבד שביר; אוטומציה מלאה (claude לכל סשן) יקרה. **הנמקה:** קלוד מתעד
בנקודות מפתח (איכותי) + `SessionEnd` כותב fallback רק כשלא תועד (כיסוי). **השלכה:** איכות גבוהה כשיש,
ורצפה מובטחת כשאין — בלי עלות טוקנים נוספת בזמן הסשן.

## D4 — תזמון מקומי (Task Scheduler), לא cron של קלוד
**הקשר:** צריך לקרוא/לכתוב קבצים מקומיים ב-18:00. **הנמקה:** `/schedule` של קלוד מריץ סוכן **בענן**
שלא רואה את `C:/Users/.../work-journal`. **השלכה:** משימות Windows מקומיות; להפצה — צריך מקבילה
ל-macOS/Linux (`launchd`/`cron`).

## D5 — קלוד מדפיס ל-stdout, node כותב את הקובץ
**הקשר:** הרצת סיכום headless. **הנמקה:** אם קלוד יכתוב את הקובץ בעצמו צריך הרשאת Write בהרצה
לא-אינטראקטיבית (שביר). במקום זאת קלוד מחזיר טקסט ב-stdout ו-node כותב. **השלכה:** אפס תלות בהרשאות;
ו-fallback מקבץ-לפי-פרויקט אם קלוד נכשל → הקובץ **תמיד** נוצר.

## D6 — ⚠️ לא `--bare`; במקום זה `WORKLOG_DISABLE=1`
**הקשר:** רצינו ש-claude ה-headless לא יפעיל את ה-worklog hooks רקורסיבית.
**מלכודת שנתקלנו בה:** `claude -p --bare` מחזיר **"Not logged in · Please run /login"** — כי `--bare`
מדלג גם על קריאת ה-auth. **הפתרון:** לא להשתמש ב-`--bare`. במקום זה ה-summary מריץ `claude -p` עם
`env WORKLOG_DISABLE=1`; שני ה-hooks יוצאים מיד אם המשתנה דלוק (תהליכי-בן יורשים env). **השלכה:**
auth נשמר, רקורסיה נמנעת. אומת: אפס רשומות/markers נוצרו בהרצת סיכום.

## D7 — היוריסטיקת fallback ב-SessionEnd
**הקשר:** לא להזביל את היומן בסשנים זעירים. **הנמקה:** כותבים fallback רק אם `count >= 2` בקשות
אנושיות אמיתיות ויש טקסט; ה-snippet = הבקשה הראשונה (≤90 תווים). **השלכה:** סשן של הודעה אחת לא
יוצר רעש; סשן מהותי לא נשאר חור.

## D8 — מקור-אמת = הפרויקט; ההתקנה החיה = פריסה
**הקשר:** המוצר מיועד להפצה לצוות. **הנמקה:** צריך מקור מתועד, ניתן-לגרסון ולאריזה, נפרד מההתקנה
החיה ב-`~/.claude`. **השלכה:** מעתה עורכים ב-`work-journal/src/` ופורסים ל-`~/.claude` (ידנית עכשיו,
דרך ה-installer בהמשך). יש לשמור על סנכרון כדי למנוע drift.

## D9 — שפת התיעוד: עברית + מונחים באנגלית
**הקשר:** הצוות דובר עברית; הפלט ליוזר בעברית. **הנמקה:** התיעוד והיומן בעברית, קוד ומזהים באנגלית.
**השלכה:** ייתכן שנוסיף README אנגלי אם תהיה הפצה רחבה יותר.

## D10 — התראות: Windows toast ללא תלות
**הקשר:** המשתמש ציפה ש"יקפוץ" משהו כשהסיכום מוכן (ברירת-המחדל הייתה קובץ בלבד). **הנמקה:** toast
מקומי דרך WinRT ב-PowerShell, **בלי מודול חיצוני** (BurntToast וכו') — חיכוך אפס בהפצה — תחת ה-AppId
של PowerShell. fail-safe (לעולם לא שובר הפקת סיכום), no-op ב-OS לא נתמך, כיבוי ב-`WORKLOG_NO_NOTIFY=1`.
**השלכה:** התראה יורה כשהסיכום היומי/שבועי נכתב. **אזהרה:** אם Focus Assist / "נא לא להפריע" דלוק,
ההתראה נכנסת ל-Action Center בשקט. נבדק מהמשימה המתוזמנת האמיתית — עובד.

## D11 — פיצול התראה (18:00) ממייל (20:30), ומייל opt-in מבוסס-config
**הקשר:** עובדים לפעמים עד מאוחר; רוצים סיכום "סופי" שכולל גם עבודה אחרי 18:00, ולא לכפות מייל על כולם.
**הנמקה:** שלוש משימות מבוססות-config: התראת **ביניים 18:00 א׳–ה׳** (קבוע לכולם, ללא מייל) ·
**מייל סופי 20:30 א׳–ה׳** (regenerate מלא של היום) · **שבועי ראשון 08:00** (סיכום השבוע שעבר + פתוחים).
התיעוד לא נעצר ב-18:00. מייל הוא **opt-in** (ברירת מחדל כבוי; מופעל ב-`--setup`), ואז ברירת-מחדל או
שעות/ימים אישיים. כל שינוי דרך `worklog-config.js` (מנוע) + `worklog-schedule.js` (רישום) **רושם מחדש
את המשימות** — אין drift בין הגדרות לתזמון. **השלכה:** גמיש פר-משתמש; הסיסמה מוצפנת DPAPI.
20:30 עדיין זמן קבוע — אם עובדים אחריו, הזנב נשאר בלוג (פתרון idle-based נדחה לעתיד).

## D12 — Google Calendar: בלוקים מעוגני-סשנים, יומן ייעודי, OAuth per-user, DPAPI
**הקשר:** תיעוד חזותי ביומן Google בלי לדרוס אירועים אמיתיים ובלי טוקני-AI נוספים.
**הנמקה:** (א) **בלוקים דטרמיניסטיים** (`worklog-blocks.js`, 0 AI) מ**זמני-סשן אמיתיים** (נלכדים ב-SessionEnd) +
רשומות הלוג — מעוגני-סשנים, גזומי-פערים (לא טוענים זמן-סרק). (ב) **יומן ייעודי "Work Journal"** + תיוג
`worklog=<date>` → regenerate-and-replace בטוח, נוגעים אך ורק באירועים שלנו. (ג) **OAuth2 client לכל משתמש**,
loopback, refresh token **מוצפן DPAPI** (כמו D11/D6). (ד) **טריגר מתוך הסיכום** בריצת ה-20:30, spawn נפרד
**fail-safe**; משימת 20:30 נרשמת אם email **או** calendar. **השלכה:** opt-in, ללא npm, Windows-first;
8 מקרי-קצה מתועדים (E0–E7 ב-CALENDAR-SPEC); הבלוקים קירוב — אירוע "סיכום היום" נושא את הנרטיב המדויק.

## מלכודות פתוחות / לשים לב בהמשך
- **ניידוּת נתיבים** — `CLAUDE.md`, `SKILL.md`, `settings.json`, והמשימות מכילים נתיבים קשיחים של sarit.
  ה-installer חייב להחליף אותם בזמן התקנה (placeholders → ערכים מקומיים).
- **macOS/Linux** — אין Task Scheduler; צריך `launchd`/`cron`.
- **הרשאת auth בהרצה מתוזמנת** — המשימה רצה בקונטקסט המשתמש ומשתמשת ב-auth השמור (`~/.claude.json`).
  על מכונה ללא login אינטראקטיבי יצטרכו `ANTHROPIC_API_KEY`.
- **stdin בהוקים על Windows** — `fs.readFileSync(0)` עבד; לשים לב אם משתנה ב-runtimes אחרים.
